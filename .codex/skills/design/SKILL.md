# UI Design

Read `AGENTS.md`, `docs/prompt/main.md`, `docs/design/DESIGN.md`, `docs/design/patterns.md`, `docs/architecture.md`, and the relevant page brief before proposing a design.

1. State the page goal, data, actions, and non-goals.
2. Produce a high-fidelity mockup or a prompt for the visual prototyping tool, constrained to shadcn/ui and Tailwind.
3. Cover loading, empty, error, populated, and consequential confirmation states.
4. Use progressive disclosure and preserve English/French readiness.
5. Treat `PAPER` and `LIVE` as the same flow with a visible mode label.
6. Propose a `DESIGN.md` or pattern change only when the work establishes a reusable convention; obtain approval before changing a permanent rule.

Do not implement production code unless explicitly asked.
